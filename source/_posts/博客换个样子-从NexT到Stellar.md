## 为什么想改博客

之前博客用的是 NexT Gemini。写文章没什么问题，但随着内容慢慢增加，首页看起来有些不方便：打开就是一整篇文章，第一篇稍微长一点，其他内容就被挤到很后面了。

Java 学习、AI 工具和开源贡献也都混在时间列表里。知道标题时可以搜索，不知道具体有哪些内容，就只能往下翻。

所以这次想把博客的展示方式重新整理一下。文章还是主要内容，首页先让人看清楚我写了什么、可以从哪里开始读。

## 为什么换成 Stellar

一开始也考虑过保留 NexT，只调整摘要、配色和侧栏。这个方案改动少，而且也能解决首页展开全文的问题。

不过有了 AI 怕什么工作量（误），我还希望把相关笔记组织起来，后面继续补文章时，读者能沿着同一个方向看下去。[Stellar](https://xaoxuu.com/wiki/stellar/) 提供博客、专栏和文档等内容组织方式，比较符合这个需求，最后就选了它。

## 首页重新分一下工

现在首页主要放四部分：

- 简单介绍自己，提供关于我和 GitHub 入口。
- 放三篇精选：Kestra PR、weconnected 项目和后端实习经历。
- 提供 Java 后端、算法基础、AI 与开发工具、开源实践四个专题。
- 展示最近六篇文章，完整列表放到 `/blog/`，每页十篇。

精选方便第一次来的读者了解我写过什么，最近文章方便看更新。分类、标签和归档也保留着，按自己的习惯找就行。

配色用了暖浅灰背景、深灰正文和少量琥珀色，呼应 DarkYellowCat。猫标识也统一用在首页、侧栏和网站图标上。正文以清楚为主，减少动画和明显的阴影。

![改版后的桌面首页：个人介绍、三篇精选和四个专题入口](home-desktop.png)

专题里的篇数和最近文章都从现有内容自动生成，后面写文章不需要再手动改数字。

## 换主题时遇到的几个问题

### 构建成功，页面却还是不对

第一次生成后，页面布局明显不正常，控制台也有脚本错误。检查输出文件才发现，同名的 CSS、JavaScript 文件还残留着 NexT 的内容，新主题的结构配上旧资源，导致出现问题。

这次清理 Hexo 缓存和生成目录后，重新构建才正常：

```powershell
npm run clean
npm run build
```

这里的两个命令对应我仓库里的 `hexo clean` 和 `hexo generate`。[Hexo 文档](https://hexo.io/docs/commands#clean)说明，`clean` 会清理缓存文件和生成的 `public` 目录。遇到换主题后样式异常，可以先检查这一层，不用急着改 CSS。

### 目录显示了，点击却没反应

旧博客装过 `hexo-toc`。迁移后目录能显示出来，但链接不能正常跳到标题。

排查发现，这个插件会把标题的 `id` 移到内部的 `span` 上，影响了 Stellar 的目录生成。移除旧插件、清理后重新构建，改用主题原生目录，跳转就正常了。

### 手机端

桌面端看起来正常后，手机上又发现了几个问题：文章底部的长英文标题撑出了页面，悬浮按钮会盖住正文和专题入口，顶部面包屑也被阅读时长挤得逐字换行。

处理方式都比较直接：长标题允许换行，导航和目录移到独立顶栏，并预留页面空间；窄屏下把阅读时长单独放一行。

![手机端文章阅读页面：导航与目录位于顶栏，面包屑和阅读时长分行显示](article-mobile.png)

代码和宽表格则保留在自己的区域内横向滚动，避免把整个页面一起撑宽。

## 改完之后，继续写文章

这次除了构建，还检查了桌面、平板和手机宽度，以及搜索、目录跳转、图片放大、长代码和表格。构建通过只能说明页面生成出来了，按钮有没有挡住文字，还是要打开看。

以后加文章时，需要归入专题就补上对应信息，摘要也尽量写一句，可能会逃掉：

```yaml
collection:
  profile: topic
  id: tools
description: "这篇文章主要记录什么，或者解决了什么问题。"
```

这段是本站的配置示例，`tools` 对应“AI 与开发工具”，其他专题使用各自的标识。
