## 为什么放弃 cc-switch

在使用外模时，因为网络问题，我们常常要等待 `Reconnecting ... 5/5` 后才能开始工作。任务还没开始，先和重连提示对视一会儿。

之前我尝试调整连接方式，希望能减少这种等待。但在更新 cc-switch 后，又出现了重连的情况。

搜索时，我看到 GitHub 上也有人提交过相关 PR，于是开始排查 cc-switch 这一层。不过，单靠我遇到的现象，还不能把所有重连都归因于它。

经过一系列配置仍无效后，我又尝试备份并降级到 3.x。这里也遇到了版本间数据结构变化的问题，不能直接拿新版数据给旧版用；而降级之后，又缺少对一些后来出现的工具的兼容。

折腾一圈后，我最终选择了 [magpie](https://usemagpie.ai/zh/)。这里分享一下它吸引我的几个地方。

## magpie 是什么

magpie 是在本地运行的模型网关：Agent 先把请求交给 magpie，再由它转给对应的模型供应商。

供应商添加一次后，就可以给不同的 Agent 选择模型，支持 Windows、macOS 和 Linux，也提供命令行和 TUI。

## 更灵活的路由模式

当手里有多个供应商或账号时，只能手动切换就比较麻烦了。尤其是任务跑到一半，一个账号额度耗尽，还得停下来改配置。

magpie 可以把多个模型或账号组成一个路由组，再让 Agent 使用这个组。

![magpie 路由页面：请求记录、自动路由组与路由模板](routing.png)

根据官方介绍，它提供按顺序、轮流、用量少的优先等模式，智能模式还会考虑账号额度的重置时间。某个账号遇到限流或故障时，也可以尝试切到其他可用账号。

另一个有意思的功能是**按意图路由**：给模型写明用途，例如“简单提问”“编写或修复测试”，由分类模型在每轮对话开始时判断交给谁处理。这一轮后续的工具调用也会留在选中的模型上，不是每调用一次工具就重新抽签。

对同时使用多个模型的人来说，这比反复手动选择更方便。但前提仍然是组里有可用的备用账号或模型，不能指望网关解决所有网络问题。

## 更详细的用量查询

我比较喜欢 magpie 的用量页面。除了总 Token，还能看到缓存读取、请求失败、输出速度和首字耗时，也可以按 Agent、模型、供应商等维度筛选。

![magpie 用量页面：Token、费用估算、缓存命中率和请求明细](usage.png)

## 隐私脱敏

这是查阅文档时发现的另一个值得关注的功能，不过我目前用不到，只做介绍。


magpie 提供本地脱敏：在请求离开电脑前，把识别到的敏感值换成占位符，模型回复里的占位符再恢复成原值。这样模型可以引用这个值，但不需要知道它具体是什么。

它可以按规则识别常见密钥、Token 等内容，也能按需开启个人信息脱敏、添加自定义词，或借助本地模型查找人名和地址。脱敏记录里还可以查看哪些内容被替换。

**这个功能默认关闭，需要在“设置 → 隐私”中开启。** 可以先用页面里的“试一试”检查自己的配置片段，确认规则是否生效。

不过它只处理经过 magpie 的请求，也不能保证识别所有敏感信息，图片和文件数据仍会原样发送，截图里的文字不会被遮盖。任务如果需要分析某个值本身，遮掉之后也会影响判断，要按需要设置例外。

## 模型和 Agent 可以分开选

有时我喜欢一个 Agent 的交互方式，但又想用另一个厂商的模型。这里就涉及不同接口协议的兼容。

magpie 支持 OpenAI、Anthropic 和 Gemini 等接口之间的转换，让 Agent 和模型不必固定绑定。例如，官方文档给出了 Claude Code 使用 ChatGPT 订阅模型、Codex 使用 DeepSeek 等用法。

它也支持把已有登录的订阅作为供应商，或者直接在 magpie 中添加支持的订阅账号，减少在不同工具之间重复配置的麻烦。

## 保存方案，减少重复改配置

官方还提供了“方案”功能，可以保存一组 Agent 的模型设置，之后一起切换。

平时学习用一套成本较低的模型，处理复杂任务时再换一套，不必逐个 Agent 调整。选回原生模型时，也支持恢复相关配置。

它在文档中强调只修改需要的配置项，并保留注释、顺序和缩进。

## 简单上手

具体步骤可以看官方[快速上手](https://usemagpie.ai/docs/zh/start)，基本流程不复杂：

1. 从官网下载对应系统的版本。
2. 在“供应商”里添加 API 供应商或支持的订阅账号，也可以导入已有配置。
3. 在“Agent”里选择要使用的模型，或者先建路由组再选择。
4. 开一个新会话，在路由和用量页面确认请求是否正常经过 magpie。

如果需要隐私保护，记得额外开启脱敏。
