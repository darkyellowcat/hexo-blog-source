# DarkYellowCat 博客写作风格指南

当用户要求撰写或润色博客文章时，遵循以下风格规范。

## 文章结构模式

根据文章类型选择对应结构：

### 踩坑/问题解决类
```
背景 → 报错信息 → 排查过程（分步骤） → 解决方案 → 总结
```

### 学习笔记类
```
简介/引言（为什么学） → 核心概念 → 分类/对比 → 代码实现 → 例题/实战 → 复杂度分析或总结
```

### 工具推荐类
```
引言（痛点） → 简介 → 核心功能（列表） → 使用指南 → 总结
```

### 项目记录类
```
缘由/动机 → 项目概览（功能+技术栈） → 设计亮点 → 挑战与收获 → 下一步计划
```

## 语言风格

- 中文为主，技术术语保留英文原文并加粗：**Spring Boot 3**、**Redis**、**BCrypt**
- 口语化但不随意，像在跟同学讲解：「让本就没有专门训练的鄙人在循环中有些裂开」「一句话让我的困意瞬间消失」
- 适度自嘲和幽默，展现真实的学习过程，不装专家
- 会坦诚说明自己的局限：「目前还在写，先插个眼」「虽然感觉可能性不大，但不能实锤」
- 第一人称叙述，有个人经历作为引入动机

## 格式规范

- front-matter 必须包含：title、date、categories、tags
- 使用 `##` 和 `###` 组织层级，不滥用 `#`（仅用于顶级大节）
- 代码块标注语言类型（java、bash、xml、yaml）
- 关键结论用引用块 `>` 突出
- 列表用于枚举功能、优缺点、步骤
- 分隔线 `---` 用于排查步骤之间的视觉分隔
- 适度使用 emoji（标题前缀或引用块内），不过度装饰

## 内容特征

- 重视「为什么」：不只写怎么做，要写为什么这样做、为什么会出这个问题
- 排查过程完整呈现：展示思考路径，包括走过的弯路和排除的错误方向
- 代码给完整可运行的示例，不给片段
- 会引用权威来源（官方文档、oi-wiki、力扣链接）
- 学习笔记类文章会附带对应的练习题目链接
- 总结部分简洁有力，用列表归纳要点

## 技术领域

主要覆盖：Java 后端（Spring Boot、MyBatis、Spring Security）、数据库（MySQL、Redis）、算法与数据结构、开发工具、项目实战。以后端视角理解和解释问题。

## 生成 front-matter 示例

```yaml
---
title: 文章标题（简洁明确，可带技术关键词）
date: YYYY-MM-DD HH:mm:ss
categories:
  - 学习笔记 | 踩坑 | 工具推荐 | 开发笔记 | 博客搭建
tags:
  - 具体技术标签1
  - 具体技术标签2
---
```
